# 轻知闯关 MVP 运行与验收

小程序使用 Taro 4.3.3 的 React + TypeScript 项目模板。PostgreSQL 16 运行在 Docker Compose，FastAPI、AI 工作进程和 Taro 构建运行在宿主机。

## 本机启动

准备 Docker Compose、Node.js 20.18 或更高版本、npm 和 uv。后端的 `.python-version` 指定 Python 3.12。

在仓库根目录启动数据库，在后端目录建立本机配置并执行迁移。

```bash
docker compose up -d --wait postgres
cd backend
cp -n .env.example .env
uv sync --locked
uv run --locked alembic upgrade head
uv run --locked uvicorn app.main:app --host 127.0.0.1 --port 8000
```

数据库端口为 `127.0.0.1:55432`，API 文档在 `http://127.0.0.1:8000/docs`。开发配置的 `APP_ENV=development` 提供本地测试会话。

将实际的 `DASHSCOPE_API_KEY` 和 `TAVILY_API_KEY` 写入 `backend/.env`，再从另一个终端启动工作进程。默认 `AI_PROVIDER=qwen`，经百炼 OpenAI 兼容地址 `DASHSCOPE_BASE_URL` 调用 `qwen-flash`，用于理解意图、出题、核验和通关总结。若需要在控制台使用专属地址，覆盖 `DASHSCOPE_BASE_URL`；模型名可用 `QWEN_MODEL` 调整。Tavily 用于自由主题的实时资料检索。配置变更后重新启动工作进程。每日出题限额默认为每用户 8 组、全局 500 组。每日总结模型调用限额默认为每用户 24 次、全局 1,200 次。练习开启次数默认为每用户每日 200 次，用于限制异常重复建答。限额可通过 [后端配置](../backend/app/config.py) 对应的环境变量调整。

DeepSeek 仍保留为回退供应商：在 `.env` 设置 `AI_PROVIDER=deepseek` 并配置 `DEEPSEEK_API_KEY`，工作进程会改用 `langchain-deepseek` 和 `DEEPSEEK_MODEL`。两条路径共用同一套题组校验、逐题核验和修正预算。若所选供应商的密钥缺失、另一家密钥已配置，工作进程会记录告警并自动改用已配置的供应商。

```bash
cd backend
uv run --locked python -m app.worker
```

从仓库根目录构建本地小程序。微信开发者工具可导入 `frontend`，项目配置将运行目录指向 `frontend/dist`。

```bash
cd frontend
npm ci
QINGZHI_DEV_AUTH=1 npm run dev:weapp
```

默认开发接口为 `http://127.0.0.1:8000`。在本机微信开发者工具预览时，允许项目请求这个本地开发地址。若只想练习固定的 12 道题，可附加 `QINGZHI_DEV_FIXED_QUIZ=1`，首页会显示固定题组入口，答题和历史可在没有模型密钥时运行。AI 出题和总结需要工作进程。

正式构建使用 `TARO_APP_ID` 和配置进微信小程序的 HTTPS API 域名；Taro 构建时会用 `TARO_APP_ID` 覆盖 `frontend/project.config.json` 的 appid，未设置时保留 `touristappid`。生产构建缺少 `QINGZHI_API_BASE_URL` 会直接失败。再用微信开发者工具导入生成的 `frontend/dist`。后端使用 `APP_ENV=production`，同时配置同一小程序的 `WECHAT_APP_ID`、`WECHAT_APP_SECRET` 和所选模型的密钥。

```bash
cd frontend
TARO_APP_ID=wx-your-app-id QINGZHI_API_BASE_URL=https://api.example.com npm run build:weapp
```

生产环境通常由反向代理终止 TLS。若 Uvicorn 与代理不在同一回环地址，启动时需加 `--proxy-headers --forwarded-allow-ips=<代理地址>`，否则登录限流会把所有请求记到代理 IP 上。代理地址应按实际网络配置收紧，不要使用不受限的 `*`。

## 验收命令

从仓库根目录运行以下命令。后端测试在 Compose 创建的 `qingzhi_test` 库中逐测试迁移临时 schema。真实千问的完整链路脚本使用开发会话和本地 HTTP API。

```bash
(cd backend && uv run --locked pytest --cov=app --cov-branch --cov-report=term-missing)
(cd backend && uv run --locked alembic check)
(cd backend && uv run --locked ruff check . && uv run --locked ruff format --check .)
npm --prefix frontend test
npm --prefix frontend run typecheck
(cd backend && uv run --locked python scripts/smoke.py)
```

实时检索验收需要配置 Tavily 密钥。以下命令使用新主题，检查出题状态、12 道题的依据，以及进入答题之前主题是否已保存。

```bash
(cd backend && uv run --locked python scripts/smoke.py --topic '什么是 Vibe Coding？' --expect-saved-topic)
```

千问接入的真实验收还可直接核对兼容地址上的 JSON 输出，避免把价格和可用性判断建立在文档描述上。命令只打印供应商、模型和题数，不输出密钥或完整题组。

```bash
(cd backend && uv run --locked python - <<'PY'
from app.config import Settings
from app.domain.quizzes import validate_quiz
from app.domain.topics import get_topic_version
from app.worker.ai import build_ai

settings = Settings()
ai = build_ai(settings)
topic = get_topic_version("seasons", "v1")
quiz = ai.generate(topic)
validate_quiz(quiz, topic)
print(settings.ai_provider, ai.model, len(quiz["questions"]))
PY
)
```

如有接口变更，从当前后端导出契约并重新生成小程序类型。

```bash
(cd backend && uv run --locked python -c 'import json; from app.config import Settings; from app.main import create_app; print(json.dumps(create_app(Settings(app_env="development")).openapi(), ensure_ascii=False))') > /tmp/qingzhi-openapi.json
npm --prefix frontend run types:api -- /tmp/qingzhi-openapi.json
```

记录验收时使用的主题、公开来源、各阶段用时及核验结果。接口测试通过后，仍需逐组抽查实际生成题的依据、答案和讲解。
